# features/map — 세계 지도 (F-04)

## 책임

- 화면 전체 평면 지도, 선택 연도의 역사 국경, 사건 핀, 시점 바(`ViewpointBar`), 국경 데이터 출처 표기(`Attribution`).

## 지도

- 투영: **평면 메르카토르**(`geoMercator`), 위도 85°N ~ 85°S(남극까지, 지도 좌표 y `MAP_TOP` ~ `MAP_BOTTOM`). 좌표 원점(y = 0)과 배율 기준 높이 `MAP_HEIGHT`는 예전 범위 82°N ~ 58°S 그대로(배율 1 = 이 높이가 지도 칸 높이 - 저장된 시점·영상 장면 배율이 그대로). 값은 공용 `components/map/projection.ts`, `baseMap.ts`가 다시 내보낸다. `makeProjection(centerLon)`만 쓴다.
- 크기: 배율 1에서 세로(위도 전체)를 화면 높이에 맞추고, 가로는 화면 비율만큼 보여준다(ResizeObserver로 viewBox 계산). 화면이 360°보다 넓으면 좌우에 지도를 이어 붙인다. 지도는 하단 바 위 영역(`bottom: var(--bar-h)`)에만 그린다.
- 확대(배율 1~16, `useUi.zoom`): 휠(커서 위치 고정), 두 손가락 핀치, 두 번 클릭·손가락 두 번 탭(iOS는 dblclick이 안 올 때가 있어 onPointerUp에서 직접 판정, 뒤따르는 dblclick은 무시)(+/− 버튼은 없앰 — 지도를 가려서). 가로 이동은 회전(lon), 세로 이동은 확대했을 때만(centerY).
- 확대해도 핀·글자·국경선은 화면에서 거의 같은 크기(핀·글자는 ÷배율, 선은 svg의 CSS 변수 `--px`(화면 1px = 지도 몇 단위)로 굵기를 나눔 - `vector-effect: non-scaling-stroke`는 배율이 바뀔 때마다 WebKit이 국경 수백 개 선 모양을 다시 계산해 손을 뗀 뒤 다시 그릴 때 35~55ms 더 걸렸다). 확대할수록 작은 나라 이름도 표시.
- 나라를 누르면 강조(진하게 + 테두리)하고 이름을 항상 표시. 다시 누르면 해제.
- 바탕: `world-atlas/land-110m.json` 해안선(현대). 그 위에 연도별 국경.
- 시점: `data/viewpoints.ts`의 9개 경도. 시점이 바뀌면 600ms 동안 가까운 방향으로 회전, 끝나면 `centerLon` 저장.
- 끌기: 좌우로 끌면 경도가 바뀐다(끝없이 이어짐). 끌기 시작하면 시점 선택 해제(null), 끝나면 `centerLon` 저장. 5px 미만은 핀 탭.
- 성능: 투영은 경도 0에서 한 번만 하고 회전은 지도 그룹 translate로(메르카토르에서 경도 회전 = 가로 이동). 지도 내용은 useMemo로 한 번 만들어 복사본마다 재사용(국경 `bordersLayer`는 배율과 무관, 핀·이름표 `overlayLayer`(핀·이름 svg)만 배율에 따라) → 끄는 동안 국경 경로를 다시 계산하지 않는다.
- 확대 미리보기: 핀치·휠·사건 고르기 이동처럼 배율이 바뀌는 동안에는 `zoomRef`·`lonRef`·`centerYRef`만 바꾸고 이미 그린 svg를 CSS transform으로 늘리고 옮긴다(`previewZoom`, GPU). 손을 떼면(핀치)·0.15초 멈추면(휠)·애니메이션 끝에 `commitZoom`으로 한 번 그리고, 다시 그린 직후 useLayoutEffect에서 변환을 지운다(같은 프레임). viewBox 배율이 바뀔 때마다 국경 수백 개의 선 두께·모양을 다시 계산해 휴대폰 핀치가 15~24fps로 끊기던 것 → 70fps(CPU 4배 느림 측정). 미리보기 중에는 svg 크기가 변하므로 화면 크기는 부모(지도 칸) 기준으로 잰다(`mapRect`, `overlayOffset`, `mapCover`). 미리보기 동안 지도 칸 크기는 처음 한 번만 재서(`previewRect`) 쓰고, 변환 쓰기는 한 프레임에 한 번(`previewFrame`, 두 손가락이면 움직임 이벤트가 프레임마다 두 번 온다) - 움직일 때마다 재면 방금 바꾼 변환 때문에 레이아웃을 강제로 다시 해서 아이폰(WebKit)에서 빠른 핀치가 밀렸다. 미리보기 중에는 svg에 `data-preview`를 달아 고른 핀 물결을 멈춘다(globals.css).
- 층 나누기: 지도 칸(`data-map-frame`, 손짓을 받음) > 기울이는 판 > [국경 svg(바다·국경·해안선) · 지도 그림 · 핀·이름 svg(`overlayRef`)]. 핀·나라 이름·고른 사건 말풍선은 국경과 다른 svg라, 확대·끌기 미리보기 동안 같은 변환으로 옮기되 늘어난 만큼 줄인다(CSS 변수 `--pin-k` = 1/배율, `--label-k` = 배율^-0.8 - 이름 글자는 배율^0.2만큼 커지게 그리므로). 같이 늘렸다가 손을 뗀 뒤 원래 크기로 돌아가던 게 느리고 어색했다. 핀·이름 svg는 지도 칸보다 좌우 한 화면·위아래 반 화면씩 넓게(끄는 동안 화면 밖 핀·이름도 보이게, 변환 기준점 33.33% 25%). 이 svg는 터치를 받지 않고 핀(`pointer-events-auto`)만 받는다. 크기를 재는 기준은 언제나 지도 칸(`mapFrame`, 기울이거나 변환을 걸어도 그대로).
- 기울이기(`useUi.tilt`, 0~55°, 설정 메뉴 "지도 설정" 묶음 `TiltSetting` 0·30·50°): 책상 위 지도를 눈높이에서 보듯 판을 아래 가운데 축으로 눕히고 원근을 건다(`tiltParams`: 눈 거리 = 지도 칸 높이 2배, 먼 쪽 위 끝이 화면 폭이 되게 k배). WebGL 판은 판 밖 먼 쪽도 화면 끝까지 이어 그린다(`GlView.farSide`, renderer `drawRange`) - 하늘·흐림 없음. svg 대체 지도만 먼 쪽이 하늘(`--map-sky`)로 흐려진다(mask). 지도에서 직접: 마우스 오른쪽 단추·Ctrl(⌘)·Shift + 위아래 끌기, 두 손가락을 옆으로 나란히 같이 위아래로(처음 12px 움직임으로 핀치와 가름). 손짓 중에는 판 transform만 바꾸고 다시 그리지 않는다. 끌기·확대 계산은 화면 점을 눕기 전 판 위 점으로 바꿔서 한다(`toPlane`, 눈에서 그 점으로 가는 선과 판이 만나는 곳) - 기울여도 손가락 밑 지도가 따라온다. 누르기는 브라우저가 3D 변환을 거쳐 찾아 준다.
- 바라보는 방향(`useUi.heading`, 아무 각도 - 0 북쪽이 위. 돌린 만큼 계속 더한 값이라 쓰는 곳에서 0~359로): 구글 어스처럼 지도에서 직접 - 마우스 오른쪽 단추·Ctrl(⌘)·Shift + 끌기(위아래 = 기울기, 좌우 = 방향, 축은 가려지지 않은 영역 가운데), 휴대폰 두 손가락 비틀기(지도 앱처럼 핀치·옮기기·돌리기를 한꺼번에 - 두 손가락 가운데 밑 지도가 손가락을 따라 옮기고 돌고 커진다. 기울이기만 처음 움직임으로 따로 정하고, 돌리기는 처음부터 10° 비틀었거나 핀치하다가 15°(`SPIN_START`) 넘게 기울면 붙는다 - 예전에는 처음 움직임으로 핀치·돌리기 중 하나만 골라, 비틀 때 손가락 사이도 같이 벌어지면 늘 핀치가 되어 돌지 않았다. 돌린 양은 움직임마다 더해 간다). 손짓 중에는 돌리는 판(`turnRef`) transform만 바꾸고(`spinTo`, 축이 그대로 있게 가운데를 미리보기로 옮김 - WebGL 판이면 판은 건드리지 않고 headingRef만, 안 보이는 svg 판을 돌리면 손짓마다 스타일·레이아웃을 다시 했다) 놓을 때 저장(`endSpin`, 북쪽 4° 안이면 북쪽에 맞춤). 나침반(`HeadingControl`)은 돌리거나 기울였을 때만 보이고(휴대폰 오른쪽 위, 데스크톱 지도 오른쪽 아래 - 사건 패널 왼쪽·하단 바 위) 누르면 북쪽이 위·평평하게(0.45초, `resetView`), 잡고 돌리면 지도가 같이 돈다. 처음 한 번만 방법 안내(localStorage `viewHint`, 써 보거나 닫으면 다시 안 띄움). 90° 돌리기 버튼은 없앴다(사용자 결정 2026-10-21).
  - 판: 돌리지 않으면 지도 칸 그대로, 돌렸거나 돌리는 중(`useUi.spinning`)이면 지도 칸 대각선 길이의 정사각형(어느 각도에서도 모서리가 비지 않음, `planeSize`·`turnRect`·`turnStyle`). 판 모양이 바뀌면 지도 그림(snapshot)을 버리고 다시 굽는다. 배율은 화면에서 보이는 크기(배율 1 = 위도 전체가 지도 칸 높이 - 판이 크면 더 넓게 보일 뿐 같은 크기, `view`).
  - 화면 계산은 모두 돌리기 전 판 기준: `mapRect`(판 위치), `toPlane`(화면 점 → 눕힌 것 펴기 `untilt`(tilt.ts) → 돌린 것 되돌리기 `turnVec`), `mapOffset`(가려진 곳 비켜 잡기). 돌린 판은 화면보다 커서 세로 한계를 늘리지 않는다(`turnCover`). 두 손가락 기울이기·비틀기 판정은 화면 좌표(`sx`·`sy`). 나라 이름·고른 사건 말풍선은 판과 반대로 돌려(`--turn`) 화면에서 똑바로, 이름 겹침 칸도 화면 방향으로 잡는다.
  - 나침반 되돌리기는 판을 바로 북쪽으로 놓고 보이는 것만 예전 각도에서 돌아오게(Web Animations, 축은 가려지지 않은 영역 가운데), 기울기는 설정·나침반으로 바뀌면 0.45초 동안 옮겨 간다.

- 지도 그림(휴대폰·데스크톱 모두): svg 내용이 바뀌면(MutationObserver - 내용 없는 렌더는 무시) 0.5초 뒤 지금 국경 화면을 넓혀(휴대폰 좌우 두 화면·위아래 한 화면 - 확대했을 때 금방 그림 밖으로 나가서, 데스크톱은 화면이 커서 한 화면·반 화면에 해상도 2배·1600만 화소까지) canvas 한 장으로 굽는다(`components/map/snapshot.ts`의 `rasterizeSvg`, 복사본은 한 장만 글자로 바꾸고 나머지는 `<use>`로 가리킴(`extendCopies`, 굽기에서 가장 무거운 글자 바꾸기·이미지 파일 만들기를 줄임), 툴팁(title)·data-* 속성은 뺌. 배율이 그대로이고 아직 그림 안쪽이면 다시 굽지 않음(`stillCovers`). 지도 복사본 `<g>`의 key는 순번(위치로 하면 경도가 바뀔 때마다 복사본을 통째로 다시 만들었다), 해상도 1.5배·800만 화소까지). 핀치·끌기·사건 고르기 이동 동안은 svg를 숨기고(opacity 0) 이 그림만 옮기고 늘린다 - 아이폰(WebKit)은 svg를 transform으로 옮겨도 무거워 핀치·끌기 모두 밀렸고, 데스크톱도 좌우로 끌 때마다 국경·글자를 다시 그려 버벅였다. 끌기도 그림이 있으면 손을 뗄 때 한 번만 그린다(그림 밖으로 끌면 그때 한 번 그리고 예전 방식으로 이어 가다가, 끄는 중에 곧바로 새 그림을 구워 다시 그림으로). 그림은 구울 때의 화면(`snap.r`) 기준이라, 확대·이동을 그린 뒤에도(`viewCommit` 동안의 svg 변화는 내용 변화로 치지 않음) 다시 구울 때까지 그대로 쓴다 - 연달아 핀치할 때 두 번째부터 느린 길로 빠지던 문제. 화면만 바뀌면 0.3초 뒤 더 선명하게 다시 굽고, 굽는 사이 손을 대면 그만뒀다가 다시. 내용 변화는 크고 작음을 나눈다: 연도의 국경·언어·테마·나라 이름 숨기기만 큰 변화(`major`, 그림을 쓰지 않음), 핀·나라 강조 같은 작은 변화는 그림을 계속 쓰고 쉴 때 다시 구워 반영(`snapUsable`) - 핀을 누른 직후 확대·끌기가 svg 직접 이동으로 빠져 화면 끝 빈 곳·경계선이 깜빡였다. 그림이 없거나 큰 변화 뒤면 svg transform 미리보기 - 단 손으로 움직이지 않는 이동(핀을 눌러 그 자리로 가기·휠)은 내용이 조금 지난 그림이라도 쓴다(핀 강조가 바뀌어 그림을 버린 직후라, svg를 직접 옮기면 화면 끝 빈 곳·경계선이 깜빡였다). 그림 미리보기 중에는 손을 떼도 바로 그리지 않고 0.25초 쉴 때 한 번 그린다(`settle` - 다시 그리는 순간 휴대폰이 잠깐 멈춰 연달아 움직일 때 걸렸다). 끌다 놓으면 관성 이동(`fling`, 놓기 직전 0.1초 속도, 감속 325ms). 미리보기 중에 누른 탭은 svg가 보이는 자리에 없으므로 바로 그린 뒤(flushSync) 그 자리의 핀·나라를 찾는다(`stale`). 움직이는 중의 svg 내용 변화(끌기 시작 → 보는 지역이 바뀌어 핀 순위·목록이 바뀜 등)는 끝난 뒤 다시 구울 때 반영한다(`dirty`) - 바로 버리면 끌 때마다 그림을 못 쓰고 느린 길로 빠졌다(아이폰 Safari 타임라인으로 확인). 미리보기 중 svg 자신의 속성·스타일(`opacity`, `data-preview`)은 바뀔 때 한 번만 쓴다 - 같은 값을 다시 써도 WebKit은 지도 svg 전체 스타일을 다시 계산해, 매 프레임 쓰던 때 아이폰 끌기·확대가 무거웠다.

  - 원본 이름(`n`)이 바뀌면 전쟁 지도 진영(`content/campaigns/<id>/sides.txt`)도 새 이름으로 적는다.
- 변환 때 작은 조각(약 40km² 미만)은 빼고, 압축 후 뒤집힌 도형(넓이 > 반구)이 있으면 실패한다. 화면에서도 같은 검사로 걸러낸다(725~800년 지도 전체가 칠해지던 버그).
- 색은 정치체마다 고정(해시). 이름은 면적 20만 km² 이상, 큰 순서로 최대 90개(`MAX_LABELS`, 배율만큼 늘어남, 조각 수가 아니라 이름 수로 셈), 핀보다 위에(터치는 통과). 나라가 30개 이하인 시대(고대 초기)는 크기와 상관없이 모두 표시.
- 이름 겹침 방지: 큰 나라부터 놓고, 겹치면 위아래로 비켜 보고, 그래도 자리가 없으면 뺀다(선택한 나라·고대 초기는 항상 표시).

## 색·테마

- CSS 변수(`--map-ocean`, `--map-land`, `--map-border`, `--map-region-opacity`, `--map-label` 등)만 사용. SVG 속성에서 `var()`가 안 먹는 경우(fillOpacity)는 `style`로.

## 모바일 규칙

- 핀은 보이는 점 r=4, 터치 영역 r=16.
- 핀은 개수 제한 없이 모두 그리되, 화면에서 가까운 핀(핀 그림 `PIN_GROUP` 14단위 안)은 고른 사건 → 중요한 순 대표 핀 하나로 묶고 점 오른쪽 위에 "+N" 표(`lib/events.ts`의 `clusterPins`, 모양은 `pinBadge.ts` - svg와 WebGL 글자 판이 같이 씀). 배율이 바뀌면 다시 묶어 확대할수록 풀린다. 묶인 핀을 누르면 대표 사건을 고르고 묶인 사건 전부를 넘긴다(`selectFromMap(id, group)` → `useUi.selectedGroup`, 순서는 대표 → 나머지 시기 순) - 목록이 그 사건들을 한 덩어리로 붙여 둔다.
- 핀 탭 → `useUi.selectFromMap(id)` → 사건 패널이 열리고 해당 카드로 스크롤(hover 툴팁 금지). 닫혀 있었으면 모바일 시트는 절반 남짓(42% 지점)만 연다(`panelHalf`). 시트가 점을 덮지 않게, 패널 크기가 바뀐 뒤(두 프레임 뒤) `focusOn`으로 점을 가려지지 않은 영역 가운데로 옮긴다(카드 탭과 같은 이동).
- 고른 사건에 사진이 있으면 핀 자리에 지름 44px 둥근 사진(지역 색 테두리, `-s.webp`, 받은 뒤), 말풍선은 그 위로 - WebGL은 글자 판(`GlMap` photoSpec), svg는 clipPath 이미지.
- 고른 핀: 조금 커지고, 둘레로 물결이 3번 퍼지며(`animate-pin-pulse`, 움직임 줄이기 설정이면 없음 - 무한 반복이면 가만히 있어도 지도 svg를 계속 다시 합성해 휴대폰이 바빴다), 점 위에 사건 이름을 나라 이름보다 위 층에 띄운다.
- 시점 고르기 화면(시점 바)은 없앴다 — 지도를 끌어 옮긴다. 시점은 처음 화면(정적 HTML은 언어별 `homeViewpoint`: ko·zh 동아시아, en 북아메리카, es·pt 남아메리카, fr 서유럽, hi 중앙아시아, ar 서아시아. 브라우저에서는 하이드레이션 뒤 기기 시간대로 `zoneViewpoint`가 고른 시점으로 회전 없이 옮긴다 - 싱가포르의 영어 사용자가 북아메리카에서 시작하지 않게. 시점 경도는 패널에 가려지지 않은 영역의 가운데에 온다(`overlayOffset`, 사건 고르기 이동과 같은 계산 - 데스크톱 오른쪽 패널이 가운데를 가렸다))과 사건 목록 정렬(지도 가운데와 가까운 시점의 지역부터)에만 쓰인다.
